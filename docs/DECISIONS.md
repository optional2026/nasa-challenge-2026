# Engineering decisions

| ID | Decision | Reason | Consequence |
|---|---|---|---|
| D-001 | Backend on **Starlette + Pydantic v2** with a small in-house router (`api/framework.py`) instead of FastAPI | FastAPI could not be installed in the isolated build environment; Starlette (FastAPI's foundation) and Pydantic were available and testable | Same validation model; OpenAPI 3.1 is generated from the route registry; offline docs page at `/api/docs` (no CDN). Swapping to FastAPI later is mechanical. |
| D-002 | **SQLite** via stdlib `sqlite3` with explicit DDL instead of SQLAlchemy | SQLAlchemy unavailable; SQLite needs no server and suits an onboard single-node deployment | WAL mode for concurrent simulator/sync/API; foreign keys enforced; migrations would be added with a migration tool in production. |
| D-003 | Frontend uses React + TypeScript with a **Vite** config, plus an **esbuild** offline build script | Vite could not be installed in the build environment; esbuild was | `npm run dev/build` works on a normal machine; `frontend/dist` was built and tested here with `node build.mjs`. |
| D-004 | **SVG chart components** instead of Recharts | Recharts could not be installed, so Recharts code could not be compiled or tested; shipping untested chart code was rejected | `components/Charts.tsx`: line/step series, baseline band, reference lines, alert markers, dual axis, tooltips, click-to-inspect; no runtime dependency. Recharts can replace it behind the same props if desired. |
| D-005 | All numeric alert criteria live in `rules.json` with a **rule class** | Spec forbids invented clinical thresholds | Only two NASA-referenced operational rules (CO₂ [V2 6004] 3 mmHg habitat 1-h average; 8.5 h sleep-scheduling reference [V1 6001]) use NASA numbers; all others are baseline-relative DEMONSTRATION_ONLY rules; the clinician rule ships inactive. |
| D-006 | Baselines are per astronaut × indicator × **context** | Resting vs exercise heart rate, different performance tests and daily water totals are not comparable | Exercise/sleep heart rate is stored and charted but not compared with the resting baseline. |
| D-007 | Private behavioral data visible to the **astronaut and the flight surgeon**; the onboard CMO sees that a private item exists, redacted | Spec requires stricter access for behavioral information; NASA uses private medical conferences with flight surgeons ([V1 6002]) | CMO cannot read check-ins; WebSocket events are redacted the same way. |
| D-008 | Administrator role has **no medical data access** | Least privilege | Admin sees operations pages only. |
| D-009 | Simulator controlled from the UI uses an **in-process transport** that calls the same handler functions as the HTTP routes; the CLI uses real HTTP | Keeps the demo self-contained while exercising identical validation/assessment code | Documented in `simulator/source.py`. Both paths are tested. |
| D-010 | Ground segment is a **simulated in-process ground station** | No ground system exists for the hackathon | Clearly labelled "SIMULATED" in API and UI; `send()` interface is replaceable. |
| D-011 | Symptom reports are their own observations (`metric_code=symptom`, source `manual`) linked to the measurement they were reported with | Symptoms are self-reports and must not inherit device provenance | Reports and combined rules use symptom onset and severity. |
| D-012 | Timestamps stored as millisecond UTC strings `YYYY-MM-DDTHH:MM:SS.mmmZ` | Sortable, explicit, timezone-safe in SQLite | Inputs without a timezone are rejected. |
| D-013 | WebSockets plus a **10 s polling fallback** in the UI | The sandbox's Uvicorn lacked a WebSocket implementation; real crew networks can also drop sockets | UI stays current either way; `uvicorn[standard]` provides WebSockets on normal installs. |
| D-014 | The CMO's own record (AST-002) is visible to them unredacted | They are the astronaut for that record | Consistent with "the astronaut themself". |
